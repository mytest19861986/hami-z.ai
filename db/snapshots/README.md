# اسنپ‌شات‌های بازیابی دیتابیس (Sandbox Recovery)

سندباکس گاهی هنگام بازیابی، فایل `db/custom.db` را (که untracked است و در گیت نیست) حذف و یک دیتابیس خالی فقط-شِما می‌سازد. نتیجه: خطای ۵۰۰ در ورود (`Prisma P2025` — نبود نقش `USER`) و پیام «خطا در ارتباط با سرور» در مرورگر.

## راه‌حل پایدار

آخرین اسنپ‌شات سالم دیتابیس در همین پوشه به‌صورت **tracked در گیت** نگهداری می‌شود تا هر بازنشانی سندباکس، آن را هم بازیابی کند:

- `custom-snapshot.db` — آخرین اسنپ‌شات کامل (کاربران، نقش‌ها، طرح‌ها، پزشکان، عضویت‌ها، کیف پول)

## استفاده

بعد از هر بازنشانی سندباکس (یا هر وقت ورود خطای سرور داد) فقط این را اجرا کنید:

```bash
bash scripts/restore-db.sh
```

اسکریپت: اسنپ‌شات را جایگزین `db/custom.db` می‌کند، اینوارینت‌های امنیتی (`prisma/invariants.sql`) را اعمال می‌کند، سلامت ادمین را چک می‌کند و سرور dev را در صورت نیاز بالا می‌آورد.

## به‌روزرسانی اسنپ‌شات

هر وقت داده‌های معناداری اضافه شد (کاربر واقعی، طرح جدید و…) اسنپ‌شات را تازه کنید و کامیت کنید:

```bash
bash scripts/restore-db.sh --update-snapshot
```

> ⚠️ اسنپ‌شات شامل داده کاربران است و در مخزن گیت عمومی قرار می‌گیرد؛ فقط برای محیط توسعه/دمو استفاده شود. برای دیتای واقعی production دیتابیس خارجی (Postgres) توصیه می‌شود.
